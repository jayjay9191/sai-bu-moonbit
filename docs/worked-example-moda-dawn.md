# 引用校验与投稿包认证：完整案例

本文是赛簿“引用校验追踪”的完整演示：一次规则判定如何从
“规则适用条件 → 来源证据 → 结论”走完，每一步都能指着来源说话。

背景：2026-11-18 报名初审驳回指出，申报书承诺的引用校验与投稿包认证，
缺少从规则适用条件、来源证据到结论的清晰机制和代表性案例。
本文就是那个机制的代表性案例，全部用真实台账数据。
机制实现在 `evidence.mbt`，复现命令：

```sh
moon run cmd/main trace 第零次黎明 "魔搭 AI+∞ 第三期「AI 造游戏」"
moon run cmd/main trace 验价尺 "第二十届全国大学生软件创新大赛"
moon run cmd/main trace 第零次黎明 "松江·创世纪 AI 游戏大赛"
```

## 机制：三步链

1. 规则适用条件：每条规则收录原文引用、来源与核实日期，不只存一个
   布尔标志。没收录原文引用的规则，追踪会写明“未收录”，不编一条
   假原文顶上。
2. 来源证据：每件作品的每条事实（首次公开时间、已投比赛）带证据与
   来源，只收录台账里已有记录的事实，不编新数据。
3. 结论：由 MoonBit 当场算出。判定条件与 `detect_conflicts` 是同一套
   （标志位 + 台账字段），追踪只补上原文引用与事实证据，不另写一套
   判定；`evidence_test.mbt` 里“追踪与引擎 76 对全量一致”测试保证
   两者不脱节。P0 冲突直接把投稿包标为 blocked，认证拒绝并逐项写清
   原因；无冲突且材料齐全、数据已核实未过期才算可提交。

## 案例一：《第零次黎明》→ 魔搭（P0 冲突，不得投稿）

（标志位 requires_first_publish = true）。

规则原文：“参赛作品必须为活动期间首次公开发布的原创作品，
不得使用已参加其他比赛或由其他比赛产生的作品、成果参赛”。

来源：魔搭官网《参赛须知》第 1 条（AIBetas 转述官方页；
官网原文因登录墙未直接读到；核实于 2026-11-13）。

- 事实 1：作品首次公开于 2026-11-02 之前。
  证据：Combos 分享页 https://share.combos.game/p/1737054

违反“活动期间首次公开发布、不得使用已参加其他比赛的作品”。

结论：P0 冲突，不得投稿该比赛。投稿包认证随之拒绝：
blocked，且材料缺口 3 项。

## 案例二：验价尺 → 软件创新大赛（规则 3 通过，但包仍不可提交）

这个案例证明机制能区分“只公开”和“已投过”——原创条款只读
submitted_to，不读首次公开日期。

规则原文：“参赛作品必须为原创且未参加过其他国家级公开比赛的作品；
同一作品重复参加比赛，一经查实取消资格和成绩”。

来源：第二十届全国大学生软件创新大赛原创条款原文
（条款原文已收录于台账 note；核实于 2026-11-15）。

来源证据：作品未投过其他比赛（submitted_to 为空）；作品虽已公开
（首次公开于 2026-11-16，证据：GitHub 公开仓库
https://github.com/jayjay9191/yan-jia-chi-moonbit），
但本规则不读公开日期，不触发。

结论：通过——未参加过其他比赛。

但投稿包认证仍为“不可提交”，原因只有一项：材料缺口 1 项
（指定题目作品未就绪）。规则通过不等于包可提交——追踪与认证是
两道独立的检查，这正是 preflight 逐包认证的含义。

## 诚实限定

- 魔搭规则原文来自 AIBetas 对官方页的转述，官网原文因登录墙未直接
  读到；追踪里写明了这一层，不把它当成官网原文。
- AI PLAY 提案已提交的证据是用户确认（2026-11-16），未独立核实；
  但本案例的 P0 结论不依赖它——只凭“11-02 前已公开”这一条，
  公开分支就足以触发。
- 造化“须用天工引擎新做体素游戏”的规则 2 只表达“须新做”，
  不表达引擎要求；两件工具作品对造化显示“无冲突”，不等于能交
  （它们不是游戏）。
