# 参赛管家 · MoonBit 版

一个帮参赛者**同时管多个比赛**的命令行工具：12 个比赛的规则、截止、材料放进一个台账，
一件作品投不同比赛时自动检测规则冲突、生成投稿包。

参加 **2026 MoonBit 黑客松 11 月赛季**的作品。原创 MoonBit 实现，
没有复制任何其他项目的代码。

## 这是什么

对标 Lexmount 一等奖作品 Auto-Lexmount（一键全自动参赛流水线），但比它多三样东西：

1. **多比赛并行管理**——Auto-Lexmount 一次只做一个比赛；这里 12 个比赛的规则、
   截止、材料、奖金放在一个台账里统一管理。
2. **游戏作品投稿支持**——Auto-Lexmount 只会读 1–3 个公开网页做小报告，
   做不了游戏；这里能打包游戏链接、演示视频、投稿文案。
3. **冲突检测**——同一件作品投不同比赛，规则撞了就报警。核心卖点：
   魔搭要求“活动期间首次公开发布”，《第零次黎明》11-02 前已公开且已投
   Qoder / AI PLAY，工具直接报 P0，而不是悄悄交上去等取消资格。

## 怎么跑

需要 MoonBit 工具链（`moon`，0.1.20261104 或更新）。

```sh
# 1. 跑测试（19 个，全部通过才算数）
moon test

# 2. 跑 CLI：无参数跑整条流水线
#    打印 12 个比赛台账 → 冲突检测 → 截止撞期提醒 → 投稿包
moon run cmd/main

# 3. 子命令：只做一件事（作品名、比赛名含空格时加引号）
moon run cmd/main list
moon run cmd/main conflicts 第零次黎明
moon run cmd/main pack 第零次黎明 "松江·创世纪 AI 游戏大赛"
moon run cmd/main collisions
moon run cmd/main benchmark
moon run cmd/main help
```

不需要联网、不需要 API Key、不读写任何外部服务，纯本地运行。

## 60% 借鉴 / 40% 创新（诚实说明）

**借鉴 60%（学的是思路和工程做法，不是代码）：**

- 证据优先：每条比赛数据带来源与核实状态，没核到的直接标“未核实”/“待核对”，
  不编数据。数据来源是《最近要参加的比赛汇总》（2026-11-13 晚四路核实版）。
- 严格的提交前检查：投稿包生成前先跑冲突检测，P0 冲突直接把投稿包标为 blocked，
  而不是生成一份看起来能交的材料。
- 诚实标注：演示/转述/未核实的东西在数据和输出里写清楚
  （例如魔搭“首次发布”条款注明来自 AIBetas 转述，官网原文未直接读到）。
- 测试覆盖：核心逻辑（台账、冲突、投稿包）都有测试，`moon test` 全过才算完成。

**创新优化 40%（Auto-Lexmount 没有的）：**

- 多比赛并行管理（12 个比赛一个台账，按截止排序）。
- 游戏作品投稿支持（打包游戏链接 + 演示视频 + 投稿文案）。
- 跨比赛冲突检测（首次发布 / 须新做 / 截止撞期）。
- 投稿包生成（同一件作品投不同比赛，标题格式、材料清单、缺口跟着变）。

## 哪些是真实数据，哪些是演示

- **真实数据**：12 个比赛的名称、截止、奖金、赛道要求、材料清单，均来自
  2026-11-13 晚核实过的比赛汇总；《第零次黎明》的公开时间（2026-11-02 之前）
  与已投比赛（Qoder、AI PLAY）是真实记录。
- **待确认**：AI PLAY 提案是否已交未确认（用户 2026-11-15 表述含糊），
  数据里写在作品备注中，冲突检测不依赖它（只凭“11-02 前已公开”这一条
  就足以触发魔搭 P0）。
- **演示性质**：本工具目前是本地 CLI，不联网、不真的向任何比赛平台提交，
  输出的投稿包是“照着交的材料清单”，提交动作本身仍由人完成。
  Rokid 的截止（01-28 vs 01-22）等多处数字冲突已在数据里标注“待核对”。

## 环境说明

本机 MoonBit 工具链曾因 `~/.moon` 安装不完整导致 `moon test` 报错
“Cannot inject the standard library `moonbitlang/core`”，已修复：
从官方 `cli.moonbitlang.com` 下载了与工具链配套的 core 包，
解压到 `~/.moon/lib/core` 并执行了 `moon bundle`。
在网络正常的机器上，直接装官方工具链即可，不需要任何特殊配置。
