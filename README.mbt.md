# 参赛管家 · MoonBit 版

一个帮参赛者**同时管多个比赛**的命令行工具：12 个比赛的规则、截止、材料放进一个台账，
一件作品投不同比赛时自动检测规则冲突、生成投稿包。

参加 **2026 MoonBit 黑客松 11 月赛季**的作品。原创 MoonBit 实现，
没有复制任何其他项目的代码。

## 这是什么

对标 Lexmount 一等奖作品 Auto-Lexmount（一键全自动参赛流水线），但比它多三样东西：

1. **多比赛并行管理**——Auto-Lexmount 一次只做一个比赛；这里 12 个比赛的规则、
   截止、材料、奖金放在一个台账里统一管理。
2. **游戏作品投稿支持**——Auto-Lexmount 只会读 1–3 个公开网页做小报告，
   做不了游戏；这里能打包游戏链接、演示视频、投稿文案。
3. **冲突检测**——同一件作品投不同比赛，规则撞了就报警。核心卖点：
   魔搭要求“活动期间首次公开发布”，《第零次黎明》11-02 前已公开且已投
   Qoder / AI PLAY，工具直接报 P0，而不是悄悄交上去等取消资格。

## 怎么跑

需要 MoonBit 工具链（`moon`，0.1.20261104 或更新）。

```sh
# 1. 跑测试（29 个，全部通过才算数）
moon test

# 2. 跑 CLI：无参数跑整条流水线
#    打印 12 个比赛台账 → 冲突检测 → 截止撞期提醒 → 投稿包
moon run cmd/main

# 3. 子命令：只做一件事（作品名、比赛名含空格时加引号）
moon run cmd/main list
moon run cmd/main conflicts 第零次黎明
moon run cmd/main pack 第零次黎明 "松江·创世纪 AI 游戏大赛"
moon run cmd/main collisions
moon run cmd/main benchmark
moon run cmd/main validate
moon run cmd/main help
```

不需要联网、不需要 API Key、不读写任何外部服务，纯本地运行。
只有 `scripts/sync_data.py` 需要联网（抓三个公开官网核对数据）。

## 数据怎么改（JSON 是唯一数据源）

比赛数据不在 `.mbt` 代码里，全部在 `data/competitions.json`：

```sh
# 1. 改 JSON（只改这个文件）
# 2. 重新生成数据代码
python3 scripts/generate_data.py
# 3. 格式化 + 校验 + 测试（生成器输出必须先过 moon fmt 再提交）
moon fmt && moon run cmd/main -- validate && moon test
```

生成器是确定性的：同一份 JSON 每次生成字节一致；生成内容已验证
与外置前的 `competition.mbt` 数据逐字一致（135 个字符串 + 36 个布尔值）。
CI 里也有一道检查：改 JSON 却忘了重新生成，流水线会失败。

## 同步：联网核对官方信息

```sh
python3 scripts/sync_data.py            # 核实并更新（有变化才写 JSON）
python3 scripts/sync_data.py --dry-run  # 只打印报告，不改任何文件
```

覆盖 3 个公开可读的来源：MoonBit 官网（11 月轮截止是否公布，只报告）、
绿联官网（初稿截止与总奖金池）、PAYATHON 官网（两阶段最后一天与
Vibe Pay 一等奖）。其余 9 个比赛因页面打不开、登录墙、或日期不在
公开页上，脚本不碰，只在报告里列出。明确标注的值可以自动更新；
需要推断的值（PAYATHON 日历格的阶段最后一天）只核实不自动写，
对不上就报“需人工确认”。

## 对比实测（benchmark）

跑法：`moon run cmd/main benchmark`——先跑一轮全量扫描数真实结果
（全部 3 件作品 × 全部 12 个比赛的冲突检测与投稿包生成），
再把同样的全量扫描重复 100 轮计时。

2026-11-15 当场跑出来的数字：

| 指标 | 工具实测 | 人工手动核对（2026-11-15 实测） |
|---|---|---|
| 比赛数 | 12 | 12 |
| 作品数 | 3 | 3 |
| 规则评估 | 72 次/轮（每作品 × 每比赛 2 条规则） | 72 次（3 件作品 × 12 个比赛 × 2 条规则，逐格判断） |
| 发现冲突 | 4 个（P0 3 个，P1 1 个） | 4 个（P0 3 个，P1 1 个），与工具一致 |
| 生成投稿包 | 36 个，其中 P0 挡住 3 个 | 36 个，其中 P0 挡住 3 个，与工具一致 |
| 截止撞期 | 2 个日期（12-01、12-06） | 2 个日期（12-01、12-06），与工具一致 |
| 耗时 | 100 轮总计 7 毫秒，平均每轮 70 微秒 | 约 7 秒（对照已整理好的台账逐项判断 36 格） |

说明：工具一侧是 2026-11-15 在本机当场跑出来的；人工一侧是同一天
由 Muse 对照已整理好的台账逐项核对出来的，逐格底稿见
`docs/manual-baseline-2026-11-15.md`。三个诚实限定：①人工核对
不是盲测（核对前已看过工具结果），所以这次的“0 漏检”不能当强证据；
②7 秒只覆盖“对照台账逐格判断”这一步，不含整理台账本身的时间
（查 12 个比赛的规则页、核实每条规则）；③真人对照 12 个比赛的
原始规则页逐项核对，耗时只会比 7 秒更久，具体多久没测过，不编数字。
耗时是机器速度，三次跑分别是 7、8、7 毫秒，量级在几毫秒，不用当精确值较真。

## 模块说明

| 文件 | 作用 |
|---|---|
| `data/competitions.json` | 唯一数据源：12 个比赛 + 3 件作品的真实数据（改数据只改这里） |
| `scripts/generate_data.py` | 从 JSON 生成 `competition_data.mbt`（确定性输出，生成后跑 `moon fmt`） |
| `scripts/sync_data.py` | 联网核对 3 个公开官网（MoonBit / 绿联 / PAYATHON），只更新能核实的字段 |
| `competition.mbt` | 比赛台账的结构定义与按名查找（`pub(all)`，字段公开以便外部构造校验数据） |
| `competition_data.mbt` | 由生成器从 JSON 生成的台账数据，不要手改 |
| `validate.mbt` | 数据校验：名字 / 日期格式 / 材料非空 / 标志位矛盾 |
| `conflict.mbt` | 冲突检测引擎：首次发布 / 须新做 / 截止撞期（规则来自台账数据的标志位，不是按比赛硬编码） |
| `pack.mbt` | 投稿包生成：标题、一句话介绍、材料清单与缺口 |
| `cmd/main/main.mbt` | CLI 入口：无参数跑整条流水线；子命令 list / conflicts / pack / collisions / benchmark / validate / help |
| `sai-chang-guan-jia-moonbit_test.mbt` | 29 个黑盒测试（含边界测试、validate 测试、P0 文案回归测试） |
| `.github/workflows/moon-test.yml` | CI：推送时自动装 MoonBit 并跑 `moon test`（尚未在 GitHub 上跑过） |

## 60% 借鉴 / 40% 创新（诚实说明）

**借鉴 60%（学的是思路和工程做法，不是代码）：**

- 证据优先：每条比赛数据带来源与核实状态，没核到的直接标“未核实”/“待核对”，
  不编数据。数据来源是《最近要参加的比赛汇总》（2026-11-13 晚四路核实版）。
- 严格的提交前检查：投稿包生成前先跑冲突检测，P0 冲突直接把投稿包标为 blocked，
  而不是生成一份看起来能交的材料。
- 诚实标注：演示/转述/未核实的东西在数据和输出里写清楚
  （例如魔搭“首次发布”条款注明来自 AIBetas 转述，官网原文未直接读到）。
- 测试覆盖：核心逻辑（台账、冲突、投稿包）都有测试，`moon test` 全过才算完成。

**创新优化 40%（Auto-Lexmount 没有的）：**

- 多比赛并行管理（12 个比赛一个台账，按截止排序）。
- 游戏作品投稿支持（打包游戏链接 + 演示视频 + 投稿文案）。
- 跨比赛冲突检测（首次发布 / 须新做 / 截止撞期）。
- 投稿包生成（同一件作品投不同比赛，标题格式、材料清单、缺口跟着变）。

## 哪些是真实数据，哪些是演示

- **真实数据**：12 个比赛的名称、截止、奖金、赛道要求、材料清单，均来自
  2026-11-13 晚核实过的比赛汇总；《第零次黎明》的公开时间（2026-11-02 之前）
  与已投比赛（Qoder、AI PLAY）是真实记录。
- **待确认**：AI PLAY 提案是否已交未确认（用户 2026-11-15 表述含糊），
  数据里写在作品备注中，冲突检测不依赖它（只凭“11-02 前已公开”这一条
  就足以触发魔搭 P0）。
- **演示性质**：本工具目前是本地 CLI，不联网、不真的向任何比赛平台提交，
  输出的投稿包是“照着交的材料清单”，提交动作本身仍由人完成。
  Rokid 的截止（01-28 vs 01-22）等多处数字冲突已在数据里标注“待核对”。

## 环境说明

本机 MoonBit 工具链曾因 `~/.moon` 安装不完整导致 `moon test` 报错
“Cannot inject the standard library `moonbitlang/core`”，已修复：

解压到 `~/.moon/lib/core` 并执行了 `moon bundle`。
